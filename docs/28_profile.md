# プロフィール（個人情報・受取口座・セキュリティ・メール）

`/profile` に、自分に関することを1か所にまとめています。

| グループ | 項目 | 内容 |
|---|---|---|
| 個人情報と口座 | **個人情報** | 名前・メールアドレス・区分（役員/正社員/パート/派遣/従業員/業務委託/準業務委託）・源泉徴収の欄（給与の人だけ）・所属・役職・システムの権限・Mattermost連携。**表示のみ**で、変更は管理者が行う（`GET /api/profile/info`） |
| | **自宅** | 自家用車の経費（走行距離）の起点になる住所。本人・経理担当・システム管理者だけが見られる（`GET/PUT /api/profile/home`。監査ログに住所は残さない）。詳しくは `19_expenses.md` |
| | **年末調整** | 配偶者・扶養親族・各種控除・前職の分を、年ごとに入力して提出する（下の「年末調整」）。給与をもらう人（正社員・パート・従業員）と役員で、**源泉徴収が甲欄の人**だけに出る |
| | **受取口座** | 給与・報酬・立替金の振込先（全銀データに使える形式）。経理担当が確認すると振込の対象になる。`/profile#bank` で直接開ける（スマホでは折りたたみが自動で開く） |
| ログインとセキュリティ | パスワード変更 / パスキー / 2段階認証 / ログイン中の端末と履歴 | [24_security.md](24_security.md) |
| メール | メールアカウント / メール署名 | 割り当てられたアカウントの同期・接続テスト、返信に入れる署名 |

- 以前は「勤怠・給与」の中の「受取口座」タブにありました。いまは勤怠・給与の「給与明細」に、プロフィールへのリンクだけがあります。通知（口座が確認されたDM）のリンクも `/profile#bank` です。
- 口座番号は暗号化して保存し、本人と経理担当・管理者だけが見られます（[22_zengin_transfers.md](22_zengin_transfers.md)）。
- スマホでは、個人情報だけ開いた状態で、ほかは見出しをタップして開きます（[27_mobile.md](27_mobile.md)）。

実装: `src/app/(app)/profile/page.tsx`、`src/components/profile/PersonalInfoSection.tsx`・`BankAccountSection.tsx`、`src/app/api/profile/info/route.ts`。テスト: `e2e/profile.spec.ts`、`e2e/transfers.spec.ts`・`e2e/transfers.mobile.spec.ts`（口座の登録）。

## 年末調整

プロフィールの「年末調整」に、年末調整の申告に使う情報を入れます（`src/components/profile/YearEndSection.tsx`、`GET/PUT /api/profile/year-end?year=`、`POST /api/profile/year-end/submit?year=`）。

- **だれが入力するか**: 給与をもらう人（正社員・パート・従業員）と役員のうち、**源泉徴収が甲欄**の人。派遣（派遣元が行う）・業務委託・準業務委託・**乙欄の人**（従たる勤務先。年末調整はしない）には出ません（`hasYearEnd`）。
- **年**: 去年・今年・来年の3つから選びます（年末調整は1〜2月に前年分を直すことも、秋に翌年の申告書を出すこともあるため）。年ごとに別々に保存します。
- **入力項目**: 本人（寡婦・ひとり親／障害／勤労学生）、配偶者（氏名・生年月日・所得の見込み・同居・障害・国外居住）、扶養親族（最大10人。続柄つき）、保険料・ローンなどの控除（生命保険・地震保険・天引き以外の社会保険料・小規模企業共済/iDeCo・住宅ローン控除）、今年の前職（会社名・支払金額・源泉徴収税額・社会保険料）、備考。**マイナンバーは入力させません**（別の安全な方法で提出）。
- **目安の表示**: 配偶者・扶養親族ごとに、入れた内容から「どの控除になりそうか」を出します（配偶者控除／配偶者特別控除／一般・特定（19〜22歳）・老人の扶養、16歳未満は控除なし、所得が基準を超えると対象外）。年齢はその年の12月31日時点。基準は令和7年分以降のもの（合計所得58万円、配偶者特別控除は133万円、特定親族特別控除は123万円）で、`src/lib/year-end.ts` の定数です。**あくまで目安**で、最終判断は経理・人事です。
- **状態**: 下書き → 提出済み → 確認済み。保存は何度でもでき、内容を直すと（提出済み・確認済みでも）下書きに戻ります。提出するには、家族の氏名・生年月日・所得の見込みと、前職の会社名が必要です。
- **確認する人**: 経理担当・人事担当・管理者。組織 → 「年末調整」で、年ごとに全員の状態（未入力／下書き／提出済み／確認済み）と内容を見て、「確認済みにする」を押します。**見ていた版（`version` = 更新日時）を送る**ので、見てから押すまでの間に本人が直していたら 409 で確認できません。CSVも出せます（`GET /api/year-end/export?year=`。Excelで開ける BOM つき。`= + - @` で始まる文字は式にならないよう `'` を付ける）。
- **保存と記録**: 中身は JSON を AES-256-GCM で暗号化して `year_end_declarations.data_enc` に保存します（家族の氏名・生年月日・所得を含むため）。監査ログには「保存・提出・確認・一覧の閲覧・CSV出力」を残し、**氏名や金額は残しません**。

実装: `src/lib/year-end.ts`（入力の形・目安・CSV。純粋な関数）、`src/lib/year-end-server.ts`、`src/app/api/year-end/**`、`src/components/org/YearEndPanel.tsx`。テスト: `tests/unit/year-end.test.ts`、`e2e/year-end.spec.ts`。

## これから

住所・電話番号・緊急連絡先などの項目を増やす場合は、`users` に列を足して `PersonalInfoSection` に出す（本人が編集できる項目と、管理者だけが変えられる項目を分ける）。
