# カレンダー（個人に1つ・共有メールはメンバーの予定を見る入口）

**カレンダーは、個人に1つです。** 共有メールアカウントに紐づくカレンダーはありません。共有メールは、「そのメンバーのカレンダーを見る」ための入口です。画面は `/calendar`。

## 考え方

- **自分のカレンダー**（はじめに開くもの）: 自分が**持ち主**の予定と、自分が**参加者**になっている予定が入ります。
- **共有メールを選ぶ**（「見るカレンダー」で「◯◯ のメンバー」）: そのメールを見られる人（メンバー）全員のカレンダーが重なって見えます。同じ予定は、持ち主と参加者が何人いても1件だけ出ます。メンバーでない人のカレンダーは見られません。
- **予定は個人のもの**です。作った人が持ち主になり、**社内の誰が参加するか**を選べます。参加者に選ばれた人のカレンダーにも、同じ予定が入ります（招待のMattermost DMも届きます）。
- 持ち主が予定を消すと、参加者のカレンダーからも消えます。

## 権限

| 操作 | できる人 |
| --- | --- |
| 自分のカレンダーに予定を作る | ログインしている人は誰でも（共有メールの権限は要りません） |
| 予定の変更・削除（参加者の入れ替えを含む） | その予定の**持ち主**と、**作った人**。参加者は見るだけ |
| 参加者に選べる人 | 社内の人（ロックされていない人）なら誰でも。共有メールが別でもかまいません |
| ほかの人のカレンダーを見る | 同じ共有メールを見られる人（`can_view`）どうし |
| 自分のGoogleカレンダーの連携・解除・表示設定・名前変更 | 本人だけ（管理者でも、ほかの人のものは変えられません） |

## 予定ごとの情報

- API の一覧は、予定ごとに `owner`（持ち主）・`attendees`（参加者）・`can_edit`（自分が変更できるか）を返します。
- 予定の一覧には「持ち主 ほかN人」と出ます。開くと、参加者の名前・追加・削除ができます（参加者として入っている予定は、入力欄が編集できず、「◯◯さんの予定（参加者として入っています）」と出ます）。
- 画面上部の「表示する人」（共有メールを選んだときだけ）で、人ごとに表示のオン/オフを切り替えられます（「全員」「自分のみ」ボタンあり）。人ごとに色が付きます。予定は、持ち主か参加者のだれかが表示中なら出ます。
- 他のメンバーのGoogle予定は「予定ありのみ」が既定なので、詳細は共有されません。

## Googleカレンダー連携（読み取り専用の取り込み）

- 連携は `calendar.readonly` スコープ。Google側の予定は変更しません。
- **連携は個人のものです**（自分のカレンダーに取り込みます）。1人が複数のGoogleカレンダーを連携できます（連携ごとに名前・色・表示設定）。取り込んだ予定は、連携した本人が持ち主です。
- 表示モード
  - **予定ありのみ（既定）**: ラベル（既定「予定あり」、連携ごとに変更可）だけを表示。タイトル・説明・場所は**DBにも保存しません**。
  - **詳細も表示**: タイトル・場所・説明を表示。
  - 「予定ありのみ」へ切り替えると、保存済みの詳細は削除されます。
- 取り込んだ予定は個別に**こちら独自の名前**へ変更できます（`title_override`）。再同期しても保持され、空欄にすると元の表示に戻ります。
- 同期: カレンダーを開いたとき（見ている人の連携のうち、5分以上経過しているものを自動）と「今すぐ同期」。範囲は過去31日〜未来366日。
- 終日予定は UTC の0時で保存（終了日は排他的）。

### セットアップ

Google Cloud Console で Calendar API を有効化し、OAuthクライアントのリダイレクトURIに次を追加します。

```
{NEXT_PUBLIC_APP_URL}/api/calendar/google/callback
```

`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` は連絡帳同期と共通です。

### 「取り込むGoogleカレンダー」の一覧が空のとき

Googleの許可のあと、連携ごとに「取り込むGoogleカレンダーを選択」の一覧が出ます。読み込めないときは、理由と直し方が赤い枠で出ます（`/api/calendar/links/:id/calendars` が返す `error`）。

| `error` | 原因 | 直し方 |
|---|---|---|
| `api_disabled` | Google Cloud のプロジェクトで **Google Calendar API が有効になっていない**（一番多い） | Cloud Console の「APIとサービス → ライブラリ」で「Google Calendar API」を有効にし、数分待って「もう一度読み込む」 |
| `insufficient_scope` | Googleの確認画面で、カレンダーの権限のチェックを外した | 「キャンセル」で連携をやり直し、「カレンダーを表示」にチェックを入れる |
| `token_expired` | 連携が切れた | 連携をやり直す |
| `google_api_failed` | その他（Google側の一時的な不調など） | しばらくして再読み込み。続くときはサーバーのログ `[Google Calendar] calendarList failed` を見る |

一覧が空（読めるカレンダーが0件）のときも、案内が出ます。サーバーのログには、Googleの返事（先頭500文字）が残ります。トークンは暗号化して `calendar_google_links` に保存します。

## 日・週・月の表示

左上の「日／週／月」で切り替えます（はじめは月）。見ている日はどの表示でも引き継がれます（月で選んだ日 → 日 → 週 → 月）。

| 表示 | 内容 |
|---|---|
| 月 | 6週間のマス表示と、選んだ日の一覧（従来どおり） |
| 週 | 日曜〜土曜の7日を、時間軸（0〜24時）の縦並びで表示。はじめは8時の位置から見える |
| 日 | 1日だけの時間軸。予定の時刻・誰の予定か・場所が見える |

- ‹ › は表示に合わせて、1か月・1週間（7日）・1日ずつ動きます（ボタンの名前も「前の月／前の週／前の日」）。「今日」で今日に戻ります。
- 週・日の上にある「終日」の行には、終日の予定とToDo（期限の日）が出ます。時間のある予定は時間の位置に、長さのとおりの高さで表示します。**時間が重なる予定は横に並べて**表示します。日をまたぐ予定は、それぞれの日の分だけ表示します。
- 週の曜日の見出し（日付）をクリックすると、その日の「日」表示になります。
- **空いている時間をクリックすると、その時刻から1時間の予定の入力**が開きます（30分刻み。自分のカレンダーの予定になります）。
- 「表示する人」の切り替えと「ToDoも表示」は、どの表示にも効きます。
- 今日の列には現在時刻の線が出ます。スマホの週表示は、枠の中を横にスクロールします。
- 開いている表示と日はアドレスに入ります（`/calendar?view=week&date=2026-10-26`）。このアドレスで開けば同じ画面になり、アドレスがないときは前回の表示で開きます（ブラウザに保存）。

実装: `src/lib/calendar-view.ts`（表示する日・移動・見出し・重なりの並べ方。純粋な関数）、`src/components/calendar/TimeGrid.tsx`（日・週の画面）。テストは `e2e/calendar-views.spec.ts`・`e2e/calendar-views.mobile.spec.ts`・`tests/unit/calendar-view.test.ts`。

## ToDoの表示

期限つきのToDoは、自分のカレンダー（共有メールを選んだときは、メンバーのToDoも）の日のマスと、日を選んだときの一覧にも出ます（詳しくは [25_todos.md](25_todos.md)）。

## 以前のデータからの移行（`20261124000000_personal_calendar`）

- 以前の「チーム全体」の予定（持ち主なし）は、**作った人の予定**になり、そのメールを見られる全員が**参加者**になります（これまでと同じ人たちに見えます）。作った人が分からなければ、メールの持ち主→最初の管理者の順で持ち主にします。
- 持ち主のあった予定・Googleの予定・Googleの連携は、そのまま持ち主のものです。
- 予定とToDoから `mailbox_id` をなくしました（マイグレーションは何度流しても同じ結果です）。
