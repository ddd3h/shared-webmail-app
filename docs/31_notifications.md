# 通知（お知らせの一覧）

メニューの「**通知**」（ベルのアイコン、`/notifications`）は、**自分に関係することが起きたことの一覧（受信箱）**です。新しい順に並び、未読には青い点が付きます。押すと、関係する画面へ移動して既読になります。

プッシュ通知の許可・ホーム画面への追加・登録した端末などの**設定は、プロフィール › 「通知とアプリ」**（`/profile#notifications`）に移しました。通知の画面の右上の「設定」からも行けます。

## 画面

- 「すべて」と「未読（n）」の切り替え。「すべて既読にする」ボタン。30件ずつで、続きは「もっと見る」。
- 1件に、種類の印（メール・ToDo・申請・給与・人事評価・セキュリティ・お知らせ）・タイトル・本文（2行まで）・「3分前」のような時刻。
- **ベルの数**: PCは右上のベルに赤い数字（99を超えたら 99+）。スマホは下の「メニュー」のボタンに赤い点、メニューの中の「通知」に数字。1分ごと、と画面に戻ったときに数え直します。

## 何が載るか

| 種類 | 元になるもの |
|---|---|
| 新着メール（担当のスレッド） | `lib/mail/sync.ts` が以前から記録していたもの |
| 申請・承認・返金・給与明細・ToDoの割り当て・人事評価・口座の変更・セキュリティのお知らせ（新しい端末・ロック・2段階認証の変更など） | **Mattermost への DM と同じもの**。`sendDirectMessage`（`lib/mattermost-dm.ts`）が送る前に、同じ内容を通知として記録します |
| そのほか（`generic`） | プッシュ通知のワーカー |

- **Mattermost が未設定・停止中でも**、アプリの通知には残ります（送る前に記録するため）。
- DMの文章から、1行目をタイトル、末尾のアプリ内リンクを移動先、残りを本文にします（`fromDirectMessage`）。Mattermost のための書式（太字の印・逃がし文字）は外します。
- 移動先は**このアプリの中のパスだけ**（`safePath`）。他のサイトのURLや `//…` が入っていても、通知の一覧に戻します。

## しくみ

- 表: `notification_events`（`read_at` を追加。マイグレーション `20261102000000_add_notification_read_at`。それ以前の通知は既読として扱う）。
- API（すべて自分の通知だけ。他の人のものは読めない・既読にできない）:
  - `GET /api/notifications?unread=1&limit=30&before=<ISO>` → `{ items, unread, next }`
  - `POST /api/notifications/read` `{ ids: [...] }` または `{ all: true }` → `{ marked, unread }`
  - `GET /api/notifications/unread-count` → `{ count }`（ベルの数）
- ブラウザ側: 数は SWR の1つのエントリ（`hooks/useNotificationCount.ts`）。一覧で既読にすると、ベルの数も同時に変わります。

## 限界

- 古い通知は消しません（一覧は新しい順で、続きを読めます）。数が増えすぎたら、期間で消す処理を足してください。
- 通知を作るのは「Mattermost へのDM」と「新着メール」の2経路です。新しい種類のお知らせを足すときは、`sendDirectMessage` を使えば、DMと一覧の両方に出ます。
- 「通知を受け取る／受け取らない」を種類ごとに選ぶ設定はありません（プッシュの許可のオン・オフだけ）。
