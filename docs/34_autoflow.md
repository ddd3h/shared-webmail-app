# 34. オートフロー（申請・給与の自動通知）

締め日・申請期限・振込日に合わせて、Mattermost の DM（とアプリ内の通知）を自動で送り、役員・社員・準業務委託の固定の月額から毎月の給与明細の下書きを作り、社会保険料・源泉所得税などの控除も自動で計算して入れる仕組み。画面は「申請・給与」→「オートフロー」（`/autoflow`）で、経理担当と管理者だけが開けます。

**どの流れも、最初は OFF です。** 「プレビュー」で今日送る内容を確かめてから、ON にします。

## 流れ

| 流れ | 誰に | いつ | 内容 |
|---|---|---|---|
| 業務報告書 | 業務委託・準業務委託（`usesReports`）で、その期間の報告書がまだない人 | 締め日の前日／締め日／提出期限日 | 催促／締め日までに出ないと報酬が支払われない旨／それでも未提出なら再通知 |
| 経費 | 承認待ち・差戻し／却下の経費がある人。承認待ちは承認する人（管理者・部署の長）にも | 申請期限の N 日前（既定3日）／当日 | 件数と一覧（先頭5件） |
| 振込日 | 経理担当と管理者 | 振込日の N 日前（既定3日）／当日 | 件数と合計。口座の情報は載せない |

- 日付は `pay_schedules`（勤怠・給与 → 管理 → 締め日・振込日）の設定を、区分ごとに使います。祝日は考慮しません（土日だけ前倒し／後ろ倒し）。
- 「差戻し」と「却下」は、システム上は同じ状態（`rejected`）です。どちらも直して再申請できます。
- 期間は暦月ではなく「前の締め日の翌日〜締め日」で見ます（15日締めなら 9/16〜10/15 が10月分）。
- ロックされたユーザー（`locked_at`）には送りません。

## 準業務委託の報告書の警告

準業務委託の人が業務報告書を出すとき、**報告する日（`report_date`）を含む直近 N 日（既定14日）に、成功したログインが1回もなければ**、保存の前に警告を出します（設定で ON にしたときだけ。既定は OFF）。

- 判定は `login_logs`（成功したログイン）を、報告する日の終わり（日本時間）までさかのぼって探し、いちばん新しいログインの日が範囲の外なら「ログインの記録なし」です。報告する日より後のログインは数えません。
- 画面には「虚偽の報告は契約違反。報酬の返還や契約の解除、場合によっては犯罪として責任を問われる」という警告が出ます。「提出しない」（既定のボタン）か「問題ありません。提出する」を選びます。
- API は `activity_ack` が無いと `409 { error: 'activity_warning', days, last_login }` を返して保存しません。画面の判断は信用せず、毎回サーバーで調べます。
- 警告を読んで提出した報告書には `work_reports.activity_flag` / `activity_note` / `activity_ack_at` が付きます。報告書の一覧に赤い「⚠ ログインの記録なし」が出て、経理担当と管理者への「報告書が提出されました」のDMにも注意書きが入ります。
- 日付を変えて直すときだけ調べ直します（本文だけ直すときは、前の印をそのまま残します）。
- 目安であって、証拠ではありません。オフラインで作業していた人も、事実どおりなら提出できます。

## 固定報酬・賞与

毎月の額が決まっている人のために、**区分が「役員」「従業員」「正社員」「パート」「準業務委託」の人だけ**、固定の月額を登録できます（業務委託は成果で額が変わるので対象外。派遣は派遣元が給与を払い、会社が払うのは派遣料なので対象外。従来どおり明細を手で入れます）。画面は「固定報酬・賞与」タブ。

- **固定報酬**（`fixed_pay_plans`）: 人・名前（明細の題名。既定は役員は役員報酬、準業務委託は業務委託報酬、社員・パートは給与）・月額・通勤手当（月額・なければ空）・最初の月・最後の月（空なら続く）。通勤手当は月額のすぐ下の別の行（「通勤手当」）になり、月15万円までは非課税として所得税の対象から外します。同じ人で期間が重なる計画は登録できません（同じ月に二重に払うため）。名前に「賞与」は使えません。変更しても、すでにできた明細の金額は変わりません。
- **加算**（`pay_extras`, `kind=addon`）: その月の下書きに足す行（業務の追加分など。名前に「通勤」を含めると非課税の通勤手当として扱います）。**手を入れていない**（経理が明細の画面で直していない）下書きで、「支払予定」のまま全銀ファイルに入っていなければ、支給の行と控除を作り直して反映します（固定の月額と通勤手当の行は、その下書きの値のまま）。経理が明細を直したあとの下書きは、直した内容が消えないよう触らず、画面に「明細に直接足してください」と出します（`payslips.auto_edited`）。全銀ファイルに入った明細や支払済みの明細にも触りません（金額が食い違うため）。
- **賞与**（`pay_extras`, `kind=bonus`）: 登録するとすぐ、別の給与明細（支払予定）ができます。題名に「賞与」が付くので（無ければ「賞与（名目）」）、「振込」の月次まとめでは「賞与」（役員は「役員賞与」）と出ます。月次まとめの全銀データは総合振込（21）で、賞与振込（12）の区分で出したいときは「給与の振込」のタブで作ります。経費の立替金は、賞与の明細には合算しません。全銀ファイルに入った賞与や支払済みの賞与は、ここでは取り消せません。
- **下書きの自動作成**: 「流れの設定」で「固定報酬の下書き」を ON にすると、毎日の実行のたびに、その人の区分の締め日で数えて「いちばん新しい締め済みの期間」の下書きを、まだなければ作ります。下書きは `payslips`（支払予定）で、`auto_key = fixed:<ユーザーID>:<YYYY-MM>`（unique）があるので、何度実行しても1枚です。払う日は区分ごとの締め日・振込日の設定どおり。
- その月に、手で入れた明細（立替金精算と賞与を除く）がすでにある人には、二重に払わないよう作りません（プレビューに「作らない」と出ます）。ロックされた人、止めた計画、期間外の計画は作りません。
- **自動で作った下書きを経理が消した月は、毎日の自動作成では作り直しません**（作った印を `autoflow_notices` に `rule='fixed'` で残してあります。送信履歴には出ません）。その月を払わないときは、下書きを消してください。作り直したいときは「下書きを今すぐ作る」を押します。
- 下書きは、本人の「給与明細」画面にも「支払予定」として見えます（手で入れた支払予定の明細と同じ）。控除を入れる前の額なので、経理が確かめるまで本人には知らせていません。
- 「下書きを今すぐ作る」ボタンで、選んだ月の分を手で作れます（確認だけもできます）。
- **控除**: 「控除の自動計算」がOFFのとき（最初はOFF）は入りません。源泉所得税・社会保険料などは、できた下書きの明細で経理が入れてから、振込に進みます。ONのときは、次の「控除の自動計算」のとおり、下書きに控除の行が入ります。賞与の明細には、どちらの場合も控除は入りません。
- freee への連携では、役員の賞与も「役員報酬」の勘定科目に入ります（区分で決まるため）。気になる場合は freee 側で付け替えてください。

## 控除の自動計算

「流れの設定」で「控除の自動計算」をONにすると、固定報酬の下書きに、社会保険料・雇用保険料・源泉所得税・住民税の行が入ります。**最初はOFFです。** ONにする前に、「控除」のタブで一人ひとりを登録し、「試算」で金額を確かめてください。

- **対象の区分**: 役員・従業員・正社員・パート。派遣（派遣元が給与を払う）、業務委託・準業務委託（給与ではない）は、固定報酬の下書きは作っても控除は引きません。賞与にも入れません。
- **一人ひとりの登録**（`payroll_profiles`。「控除」のタブ）: 生年月日（介護保険の40〜64歳と、年金・健康保険の年齢の範囲に使う。経理と管理者だけが見られる）、健康保険・厚生年金に入っているか、雇用保険に入っているか、標準報酬月額（空なら、その月の支給から等級を引く）、扶養親族等の数、税額表（甲欄／乙欄。`users.withholding_class` を更新する）、住民税（月額・6月分は別に指定できる）。**登録がない人は、控除なしの下書きになり、警告がメモに残ります。** 役員は原則として雇用保険に入らないので、初めて登録するときは雇用保険のチェックが外れた状態で始まります（兼務役員で労働者の性格がある人だけ入れる）。パートは勤務時間などで加入が変わるので、実際に加入している保険だけにチェックを入れてください。
- **会社の設定**（「流れの設定」）: 協会けんぽの都道府県（健康保険料率に使う）、社会保険料を引く時期。既定は**翌月徴収**（10月分を11月払いの給与から引く）で、当月徴収も選べます。
- **計算する順番**: 社会保険料（健康保険・介護・子ども・子育て支援金・厚生年金）と雇用保険料 → それと非課税の通勤手当を引いた額から源泉所得税 → 住民税（通知された額をそのまま）。社会保険料と雇用保険料は、通勤手当を含む支給の合計で計算します。
  - 健康保険・介護・子ども・子育て支援金・厚生年金は、協会けんぽの料額表と同じ計算（標準報酬月額 × 料率の折半、50銭以下切り捨て・50銭を超えたら切り上げ）。介護保険料は、40歳になる日（誕生日の前日）の属する月から65歳になる日の属する月の前月まで。厚生年金は70歳の誕生日の月の前月まで、健康保険は75歳の誕生日の月の前月まで。
  - 雇用保険は一般の事業の労働者負担（令和7年度 5.5/1000、令和8年度 5/1000）。**料率の年度は、支払日ではなく賃金の締切日で決まります**（4/1以降に最初に来る締切日の賃金から新しい料率。末日締め・翌月25日払いなら、3/31締め・4/25払いは前の年度、4/30締め・5/25払いから新しい年度）。社会保険料の対象月は支払月（翌月徴収なら支払月の前月分）、源泉所得税の年分は支払日の年で決まります。
  - 源泉所得税は、国税庁の「電算機計算の特例」（甲欄）と「電算機計算」（乙欄）の式。**月額表の税額とは、10円ほど、低い給与の一部では数十円違うことがあり、年末調整で精算されます**（国税庁の説明どおり）。国税庁の計算例（3つ）と、月額表の行は単体テストで確かめています。
- **下書きの控除の行**: 健康保険料・介護保険料・子ども・子育て支援金・厚生年金保険料・雇用保険料・所得税（甲欄／乙欄）・住民税。所得税は0円でも行を残します。計算の根拠（標準報酬月額、料率、課税対象額、扶養の数）と警告は、明細のメモの「【自動計算】」以下に書きます。経理は明細の画面で、ほかの行と同じように直せます。
- **「控除を再計算」**（給与明細の画面。経理・管理者）: 自動で作った下書き（支払予定・全銀ファイル前）の、自動で入れた名前の控除の行（手で入れた欄の名前なしの「所得税」も）だけを、いまの支給の行から計算し直します。経理が足した別の控除（財形貯蓄など）や、立替金精算の行は残ります。支給の行を直したあと、登録（扶養・標準報酬月額など）を変えたあとに使います。
- **警告**（結果とメモに出る）: 登録がない／役員に雇用保険のチェックが付いたまま／生年月日が未登録／その月の保険料率が登録されていない（その場合は社会保険料を計算しない）／新しい年度の保険料率がまだ登録されていない（前の年度の料率で計算し、警告）／その年分の源泉徴収の式が登録されていない（所得税を計算しない）。
- **本人に見えること**: 下書きは本人の「給与明細」画面にも「支払予定」として見えます。メモ（計算の根拠と警告。「オートフロー → 控除で登録してください」のような経理向けの文面を含む）も同じです。経理が確かめるまで本人には知らせていませんが、画面を開けば見えます。
- **対象外（手で入れる）**: 組合健保・厚生年金基金、産前産後・育児休業の保険料免除、標準報酬月額の改定（算定基礎届・月額変更届のあと、経理が「控除」のタブで更新する）、賞与の控除、年末調整、住民税額の計算（通知額を登録する）。

### 毎年の更新

料率と税額表は `src/lib/payroll/tables.ts` に、適用期間つきで入っています。次のときに更新します（更新しないと、警告が出たまま前の料率で計算されます）。

| いつ | 何を | どこで確かめる |
|---|---|---|
| 毎年3月分（4月ごろ発表） | 協会けんぽの健康保険料率（都道府県別）・介護保険料率・子ども・子育て支援金率 | 協会けんぽ「保険料額表」 https://www.kyoukaikenpo.or.jp/about/business/insurance_rate/rate_prefectures/r08/index.html |
| 厚生年金保険料率・標準報酬月額の等級が変わるとき | `PENSION_RATES`・`GRADES`・`PENSION_MIN/MAX` | 日本年金機構・厚生労働省 https://www.mhlw.go.jp/content/001692566.pdf |
| 毎年4月 | 雇用保険の労働者負担率（`EMPLOYMENT_RATES`。期間は賃金の締切日） | 厚生労働省「雇用保険料率のご案内」 https://www.mhlw.go.jp/content/001692566.pdf |
| 毎年12月ごろ（翌年分の税額表が出たら） | 源泉徴収の式（`TAX_YEARS`）。給与所得控除・基礎控除の額が変わったとき | 国税庁「給与所得の源泉徴収税額表（電算機計算の特例）」 https://www.nta.go.jp/publication/pamph/gensen/zeigakuhyo2026/data/denshi_01.pdf と、乙欄 …/denshi_02.pdf、令和9年分以降 https://www.nta.go.jp/publication/pamph/gensen/zeigakuhyo2027/data/denshi_01.pdf |

更新したら `tests/unit/payroll.test.ts` の料額表・月額表の行も、新しい表で作り直してください。

## 振込日の一覧と「承認して確定」

経理は「申請・給与 → 振込」の月次まとめで、振込日ごとの「誰にいくら」の一覧を見て、**「承認して確定…」**を押します（既存の全銀データの作成と同じ操作で、ボタンの名前だけが変わりました。新しい状態は増やしていません）。確定するとその場で全銀データができ、作成履歴からダウンロードできます。詳しくは `docs/22_zengin_transfers.md`。

- 報酬の行に「報告書未提出」「⚠ 活動警告」の印が出ます（振り込みは止めません。「通知と経理への表示だけ」の方針です）。
- 「流れの設定」で「振込の確定の通知」をONにすると、**月次まとめ**で確定したあと、振り込まれる人にMattermostで「お振込が確定しました」と知らせます（金額なし）。これは毎日の実行ではなく、確定した瞬間に送ります。最初はOFFです。「給与の振込」「支払」のタブで作ったファイルでは送りません。
- 「振込日の準備」の通知（3日前・当日）が、この一覧を見て承認するよう、経理と管理者に知らせます。

## 動き方

- アプリの中で動く 1 日 1 回の処理（`src/instrumentation.node.ts`）。日本時間の 9 時以降の最初の 1 回で、`autoflow_runs` に今日の行が作れたときだけ動きます。9 時台を逃しても（デプロイなど）その日のうちに動きます。何も ON でない日は行を作りません。
- 同じ宛先・同じ段階・同じ題材は二度送りません。送る前に `autoflow_notices` に 1 行作り（unique）、作れたものだけ送ります。何度「今すぐ送る」を押しても、二重には届きません。
- Mattermost に届かなかった（連携していない・停止中）場合も、アプリ内の通知は残り、記録も残ります（履歴で「アプリ内のみ」と出ます）。翌日に再送はしません。
- 1 通ずつ順に送ります。

## 画面

- **流れの設定**: ON/OFF と、何日前に送るか（固定報酬の下書き、控除の自動計算と都道府県・徴収の時期、準業務委託の警告も）。保存すると監査ログ（`autoflow_config_update`）に残ります。
- **プレビュー**: 今日送る通知を、送らずに確認（文面も見られます）。確認したものを、その場で送ることもできます（`autoflow_run`）。
- **固定報酬・賞与**: 固定報酬の登録、月ごとの加算・賞与、下書きを今すぐ作る。
- **控除**: 一人ひとりの登録（生年月日・扶養親族等・標準報酬月額・住民税など）と、控除の試算。
- **送信履歴**: 直近 200 件。

## API（経理・管理者）

| Method | パス | 内容 |
|---|---|---|
| GET / PUT | `/api/autoflow/config` | 設定の読み書き |
| POST | `/api/autoflow/run` | `{ dry: false }` と明示したときだけ送る。それ以外は確認だけ |
| GET | `/api/autoflow/notices` | 送信履歴 |
| GET / POST | `/api/autoflow/plans` | 固定報酬の一覧（と登録できる人）／登録 |
| PUT / DELETE | `/api/autoflow/plans/:id` | 固定報酬の変更（止める・再開もここ）／削除 |
| GET / POST | `/api/autoflow/extras` | 月ごとの加算・賞与の一覧（`?month=`）／追加 |
| DELETE | `/api/autoflow/extras/:id` | 加算・賞与の取り消し |
| POST | `/api/autoflow/fixed/generate` | `{ month, dry? }` 指定した月の下書きを作る |
| GET | `/api/autoflow/profiles` | 控除の対象の人と、一人ひとりの登録（生年月日を含むので経理・管理者だけ） |

## データ

- `autoflow_notices`（`rule`, `stage`, `subject_key`, `user_id` が unique）／`autoflow_runs`（`run_date` が unique）。
- `fixed_pay_plans`（固定の月額と通勤手当）／`pay_extras`（加算・賞与）／`payslips.auto_key`（自動で作った下書きの二重作成を止める鍵。`fixed:…` と `bonus:…`）／`payslips.auto_edited`（経理が明細を直した印）／`payroll_profiles`（控除の計算に要る、一人ひとりの登録）。
- 設定は `app_settings` の `AUTOFLOW_CONFIG`（JSON）。

## コード

`src/lib/autoflow/`: `config.ts`（設定の形）、`plan.ts`（今日送る通知を決める純粋な関数）、`run.ts`（データを集めて送る・1日1回の枠取り）。固定報酬は `src/lib/fixed-pay.ts`（DBを使わない計算）、`fixed-pay-server.ts`（下書き・加算・賞与の作成、控除の再計算と試算）、`fixed-pay-input.ts`（APIの入力の形）。控除の計算は `src/lib/payroll/`: `tables.ts`（料率・等級表・税の式。毎年更新）、`insurance.ts`（保険料）、`withholding.ts`（源泉所得税）、`deductions.ts`（組み立てと警告）、`for-payslip.ts`（支給の行から控除を求める）、`input.ts`（APIの入力の形）。
