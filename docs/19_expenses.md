# 経費申請・立替金の返金

画面は `/expenses`（ナビの「経費」）。全員が申請でき、管理者が承認・返金処理をします。

## 流れ

```
申請（承認待ち） ─┬─ 承認 ─┬─ 立替 ───→ 返金待ち ─→ 返金済
                  │        └─ 会社負担 → 承認済（ここで完了）
                  └─ 却下（コメント必須）─→ 申請者が修正して再申請 → 承認待ち
```

- **立替**: 自分で支払った経費。承認されると「返金待ち」になり、管理者が返金済にするまでが立替金の返金です。
- **会社負担**: 会社カード等で払った経費。承認で完了し、返金対象にはなりません。

## 申請（全員）

利用日・勘定科目・件名・金額（1円以上の整数）・支払方法・備考・領収書（画像かPDF、1枚10MBまで、1申請5枚まで）。

- 承認待ちの間は編集・取り下げができます。却下された申請は修正して再申請できます（承認待ちに戻る）。
- 承認済・返金済の申請は変更できません。
- 画面上部に「承認待ち」「返金待ちの立替金」「返金済みの合計」を表示します。

## 自家用車（走行距離）の申請

勘定科目で「自家用車」を選ぶと、金額は入力せず、**自宅から行き先までの往復距離 × 1kmあたりの単価**で自動計算されます。

- **出発地**: 初期値は自宅です。プロフィールの「自宅」に住所を登録します（`users.home_address`。見られるのは本人・経理担当・システム管理者だけ）。**申請のたびに書き換えられます**（自宅以外から出発したとき。「自宅に戻す」で戻せます）。自宅が未登録でも、出発地を入力すれば申請できます。申請には、そのときの出発地が保存され、詳細に「自宅 → 行き先」（自宅から出発したとき）または「出発地 → 行き先」と出ます。
- **距離の調べ方**: 管理 › システム設定 › 経費（自家用車）で、システム管理者が3つから選びます（`ROUTE_PROVIDER`。`src/lib/route-distance.ts`）。行き先（住所・施設名）を入れて「ルートを調べて金額を計算」を押すと、出発地 → 行き先の片道を調べ、2倍を往復距離にします。往復は100m単位、金額は「km（小数1桁）× 単価」を円に四捨五入します（例: 片道12.34km → 往復24.7km × 20円 = 494円）。
  - **OpenStreetMap（無料・キー不要）**: 住所は国土地理院の住所検索で座標にし、住所でないもの（施設名）はOpenStreetMapのNominatimで探します。道のりはOSRM（OpenStreetMapの道路データ）の車のルートです。公開サーバーは軽い利用向け（社内で1日数十件ほど）のため、Nominatimは1秒に1回までに絞り、同じ場所は24時間・同じ区間は1時間覚えます。件数が増えたら、自前のOSRMサーバーのアドレスを設定できます（`OSRM_BASE_URL`）。キーがなければ、これが初期値です。
  - **Googleマップ（有料）**: Google の Routes API の最適ルート。APIキー（`GOOGLE_MAPS_API_KEY`）が必要で、使った分だけ料金がかかります。キーがあって何も選んでいないときは、これが使われます。
  - **調べない**: 地図は使わず、申請者が片道の距離（km）を自分で入力します（「本人が入力した距離」と表示され、承認者が地図で確認できます）。調べる設定のときは、手入力を受け付けません。
- **単価**: 既定は1kmあたり20円。**システム管理者**が、管理 → システム設定の「経費（自家用車）」で変更できます（1〜1000円。`MILEAGE_RATE_PER_KM`）。変更は、これから申請する分から。申請済みの金額・単価は変わりません（申請時の出発地・行き先・距離・単価を `expense_claims.mileage_*` に残します）。
- **サーバーで再計算**: 申請の金額は画面の数字ではなく、サーバーが必ず計算し直します。支払方法は常に「立替」です。申請を編集しても、出発地と行き先を変えなければ申請時の金額のままです（変えると、そのときの単価で計算し直します）。
- **Google Maps APIキー**: Googleを使うときだけ、同じ画面で設定します（Google Cloud で Routes API を有効にしたキー）。Googleは、キーがあるときだけ選べます。
- **確認**: 申請の詳細に「自宅 → 行き先（往復 ○km × ○円）」と、同じルートを開く Google マップへのリンクが出ます（承認画面も同じ）。
- **費用と上限**: 検索は1人あたり1分に20回まで、同じ自宅と行き先は1時間覚えておきます（Google の課金と、無料サービスへの負担を抑えるため）。
- テストでは、Google・国土地理院・Nominatim・OSRM の代わりに疑似サービス（`MAPS_API_URL` `GSI_URL` `NOMINATIM_URL` `OSRM_URL`、`e2e/helpers/mattermost-mock.ts`）を使います。
- 無料サービスの実物（公開サーバー）への接続は、開発環境からはできなかったため、公開されている仕様どおりに作って疑似サービスで確かめています。導入時に、実際の住所で一度試してください。

## 公共交通機関のルート（交通費）

勘定科目「交通費」には、電車・バスで移動したときの**出発・到着（駅・住所）と、出発時刻（任意）**を入れる欄があります。入れると、最適なルートを調べられます。

- **無料（いつでも）**: 「Yahoo!乗換案内で見る」「Googleマップで見る」のボタンが、出発・到着・日付・時刻を入れた状態で乗換案内を開きます（`src/lib/transit.ts`）。日本の電車の乗換を無料で調べるAPIがないため、サイトを開く方式です。
- **この画面で表示（Googleマップの設定があるとき）**: 距離の調べ方が「Googleマップ」のとき、「ルートを調べる」で、**ルートの候補（最大4つ）**が所要時間の短い順に出て、使ったルートを選べます。各候補にルートの内訳（徒歩・路線・乗換駅）・所要時間・乗換回数・運賃が出ます（Routes API の `TRANSIT`＋`computeAlternativeRoutes`。1回の検索で全候補が返ります。`src/lib/transit-route.ts`）。同じ経路は1つにまとめ、「最短」「乗換が少ない」「歩きが少ない」「運賃が安い」の印を、その点で**1つだけ一番**の候補に付けます（引き分けには付けません。`rankRoutes`）。選んだルートの要約が申請に残り、その運賃を金額に入れられます。運賃は、Googleが知っているときだけ出ます（日本の路線では出ないこともあります）。出たときは「この運賃を金額に入れる」で金額に入れられます。経路・運賃は目安なので、実際に払った金額を入れます。
- **申請に残るもの**: 出発・到着と、調べた経路の要約（`expense_claims.transit_from` / `transit_to` / `transit_summary`）。申請の詳細に出て、承認者が乗換案内のリンクで確かめられます。他の勘定科目には付きません。
- 検索は1人あたり1分に20回まで、同じ区間は30分覚えます。`POST /api/expenses/transit`（`in_app` が false のときはリンクだけを返す。`routes` が候補の一覧で、`route` は最短の1つ）。
- 運賃は Google が持っているときだけ出ます。日本の電車は運賃が出ないことが多く、駅すぱあと・NAVITIME のような**正確な運賃つきの乗換検索は有料のAPI契約**が必要です（freee の経路検索はそれを使っています）。

## 承認・返金（管理者）

- 承認待ちの一覧で承認／却下。却下には理由が必要で、申請者に表示されます。
- 管理者が2人以上いる場合、自分の申請は承認できません（他の管理者が承認）。管理者が1人だけのときは自分の申請も承認できます。
- 「返金待ち」で人ごとの返金額を確認し、申請を選んで「返金する…」。複数人分をまとめて処理できます。返金方法は2つあります。
  - **給与明細に合算する**（給与明細との自動連動。下記）
  - **別途返金済にする**: 給与とは別に振込・精算した場合。返金日・メモを記録して、すぐ「返金済」になります。
- 承認・却下・返金はすべて監査ログに残ります。

## 給与明細への自動連動

「給与明細に合算する」を選ぶと、対象月（既定は今月）の明細に自動で反映されます。

1. その人の対象月に**支払予定の明細**があれば（「給与」を優先、なければ最初の支払予定の明細）、そこに「立替金精算（N件）」の支給行を追加します。なければ「立替金精算」という名前の明細を新しく作ります。
2. 合算した申請は「給与に合算済」になります（まだ返金済ではありません）。明細には内訳（日付・件名・金額）が表示されます。
3. 明細を**「支払済」**にして保存すると、合算されていた申請が自動で**「返金済」**になります（返金日は明細の支払日。空なら今日）。
4. 支払済になる前なら、「給与に合算済」の画面で「給与明細から外す」と返金待ちに戻せます（明細の行も自動で再計算）。明細そのものを削除した場合も返金待ちに戻ります。

- 「立替金精算」の行は自動管理で、明細の編集画面では変更できません（金額は合算された申請の合計）。
- 支払済の明細には合算できません（別の月の明細、または「別途返金済」を選んでください）。
- 税・社会保険料の自動計算はしないため、立替金精算も「支給」として手取りに足されます（非課税の扱いが必要な場合は、控除の項目で調整してください）。
- 支払済にした明細を「支払予定」に戻しても、返金済になった申請は戻りません。

## 出張との紐付け

経費は、自分の承認済みの出張に紐付けられます（任意）。出張側で経費の一覧と合計を確認できます。詳細は `20_business_trips.md`。

## 領収書の扱い

- 画像（JPEG/PNG/WebP/GIF/HEIC）とPDFのみ。ダウンロードは常に「添付ファイル」として返し、ブラウザで直接開きません。
- 閲覧できるのは申請者本人と管理者のみ。ユーザーを削除すると申請とファイルも削除されます。

## 注意・未対応

- 実際の振込は行いません。「返金済」は管理者が記録するものです。
- 返金済の取り消し、月次CSV出力は未対応です。

## Mattermost通知

既存のMattermost連携（管理画面の `MATTERMOST_BASE_URL` / `MATTERMOST_BOT_TOKEN`）を使い、Botからの**DM**で通知します。宛先はメールアドレスでMattermostのユーザーを探して決めます（見つからない人にはDMしません）。

| きっかけ | 通知先 |
| --- | --- |
| 経費の申請・再申請 | 申請者以外の管理者全員 |
| 承認・却下（却下は理由つき） | 申請者 |
| 立替金の返金 | 申請者（人ごとに件数・合計・返金日をまとめて1通） |
| 立替金を給与明細に合算 | 申請者（件数・合計・対象月） |
| 業務報告書の提出 | 提出者以外の管理者全員 |
| 給与・報酬明細の登録 / 支払済への変更 | 本人（**金額はDMに書きません**） |
| 管理者による勤怠の修正 | 本人 |

- Mattermost未設定・ユーザー不明・API障害のときは通知を送らないだけで、申請などの操作は成功します（エラーはサーバーログと `mattermost_notifications` に記録）。
- 件名・コメントなど入力された文字は、@メンションやリンクを無効化してから送ります。
- 通知のオン/オフ設定はありません（常に送信）。

## 部門（承認する部署）

申請するときに、自分が所属する部署から「部門」を選びます。**選んだ部門の承認者（その部署で承認の権限のある役職の人と、上の部署の人）と管理者**が承認します。2つ以上の部署に所属する人は必ず選び、1つだけなら自動で入ります。承認待ちの一覧・申請の通知・申請の詳細に、部門が出ます。詳しくは [23_org_and_evaluations.md](23_org_and_evaluations.md)。
