# 全銀データ（一括振込）と受取口座

画面は `/transfers`（ナビの「振込データ」。**経理担当と管理者だけ**に表示）。給与・報酬と、取引先への支払を、銀行のネットバンキングに取り込める **全銀フォーマット（総合振込・給与振込・賞与振込）** のファイルにまとめます。実際の振込は銀行側で行い、このアプリはデータの作成と「払った」の記録を管理します。

## 役割

| 役割 | できること |
|---|---|
| 一般ユーザー | 自分の**受取口座**を登録（`/work` の「受取口座」タブ） |
| 経理担当 | 受取口座の確認、全銀データの作成・ダウンロード・取り消し、振込済の一括記録、取引先口座の閲覧 |
| 管理者 | 上記すべて ＋ 全銀の設定（委託者情報）の保存、経理担当の指名（`/work` →管理→「経理担当」）、**申請の承認** |

経理担当は**承認はできません**（承認は管理者だけ）。権限は users.is_accounting で持ち、管理者が付け外しします（監査ログ `accounting_role_update`）。

## 準備（最初の1回）

1. 管理者が「全銀の設定」に会社側の情報を入れる: 委託者コード（10桁。銀行と総合振込・給与振込を契約したときに割り当てられる）、委託者名（カナ）、取引銀行・支店・預金種目・口座番号。**委託者コードと口座番号は暗号化して保存**し、経理担当には「設定済みか」だけを返します。
2. 各自が「受取口座」を登録: 銀行名・銀行コード（4桁）・支店名・支店コード（3桁）・預金種目・口座番号（4〜7桁）・口座名義（カナ）。口座番号は AES-256-GCM で暗号化し、本人と経理担当・管理者だけが見られます。銀行名・支店名は漢字でも構いません（全銀データでは銀行コード・支店コードで特定し、名前欄はカナにできない場合は空白で出力）。口座名義だけは全銀の文字（全角カタカナ・英大文字・数字・ `( ) . - /` ・スペース）に変換できる必要があります。
3. 経理担当が「受取口座の確認」で、通帳の写しなどと照合して**確認済**にする。内容を変更すると確認済は自動で外れます（口座のすり替え対策）。自分の口座は、他に確認できる人がいる限り自分では確認できません。

## 給与の振込

1. 「給与の振込」で月を選ぶ。支払予定の明細が口座の状態つきで並ぶ（口座未登録・未確認の人は選べず、理由を表示）。
2. 対象を選び「全銀データを作成…」→ 振込指定日（今日〜60日先）と種別（給与／賞与）を指定。
3. 「作成履歴」からダウンロードして、銀行のネットバンキングへアップロード。
4. 銀行で振込が実行されたら「振込済にする」。**明細が一括で「支払済」になり、明細に合算した経費の立替金も精算済**になります。本人にはMattermost DMで通知されます（口座情報・金額は載せません）。

## 支払（取引先）の振込

「支払の振込」で、承認済み・口座確認済みの振込申請を選んで総合振込（種別21）のファイルを作ります。記録すると申請が「振込済」になります。振込額は申請の計算結果（請求金額 − 控除 − 先方負担の手数料）です。

## 作成時のチェックと安全策

- **全部成功か、全部失敗**: 1件でも問題（口座未登録・未確認、承認前、支払済、名義が使えない文字、0円以下など）があると、問題の一覧を出して**ファイルを作りません**。一部だけ抜けたファイルが銀行に送られる事故を防ぎます。
- **二重振込の防止**: 作成済みのファイルに含まれる明細・申請は、そのままでは再度選べません。作り直すときだけ「作成済みも含める」を選びます。
- ファイルは**作成した時点のバイト列をそのまま保存**し、履歴から何度でも同じものをダウンロードできます（ダウンロードは監査ログに記録）。
- 銀行に送る前なら「取り消す」で削除でき、対象は再び選べます。振込済の記録をしたものは取り消せません。
- 「振込済」の記録は同時に2回押されても1回だけ処理されます（2回目は409）。
- 監査ログ: `bank_account_change` / `bank_account_verify` / `zengin_settings_update` / `transfer_batch_create` / `transfer_batch_download` / `transfer_batch_paid` / `transfer_batch_cancel`。

## お金がずれないための仕組み（整合性）

- **作成と「取った」印を1つのトランザクションで**: 同時に2人が同じ明細で作成しても、先の1人だけが成功します（後の人は「他の人が先に処理しました」）。
- **全銀データに入った明細は凍結**: 支払予定のまま全銀データに入っている明細は、金額の変更・支払済への変更・削除ができません（ファイルの金額とずれるため）。変更したいときは、先にデータを取り消します。振込済になった後は従来どおり編集できます。
- **後から承認された立替金は合算されない**: 全銀データに入った明細には新しい経費が合算されず（別の「立替金精算」明細になります）、経費を外すこともできません。ファイルに入っていない金額が「支払済」と記録されるのを防ぎます。
- **「振込済」の記録は全部成功か全部失敗**: 明細・合算経費の精算・バッチの記録を1つのトランザクションで行います。途中で失敗しても何も変わらず、もう一度押せます。
- **口座の差し替え対策**: 経理担当が口座を「確認済」にするとき、画面で見ていた版（revision）を送ります。見てから押すまでの間に本人が口座を変更していたら、確認は失敗します（409）。

## セキュリティ

| 項目 | 対策 |
|---|---|
| 認可 | すべてのAPIでログインと役割を確認（`src/lib/finance-guard.ts`）。一般ユーザーは403、未ログインはログイン画面へ。全銀の設定の保存と承認は管理者のみ |
| 権限の分離 | 給与明細の作成・変更は管理者だけ。経理担当は金額を変えられず、データ作成と記録だけを行う。取引先口座の確認も管理者だけ |
| 保管 | 受取口座の番号・委託者コード・会社の口座番号は AES-256-GCM で暗号化。ログ・Mattermost通知には末尾4桁も含めない（監査ログは末尾4桁のみ） |
| 閲覧の記録 | 口座一覧（番号つき）の表示、ファイルのダウンロード、作成、振込済、取り消し、設定変更、口座の登録・変更・確認がすべて監査ログに残る |
| ファイル | 作成時のバイト列をそのまま保存し再現。`Content-Disposition: attachment`、`nosniff`、`no-store`。ファイル名はサーバーが生成 |
| 入力検証 | 銀行コード4桁・支店コード3桁・口座番号4〜7桁・金額の上限・振込指定日（今日〜60日先）・全銀で使える文字だけ。IDは最大500件 |
| 二重処理 | 二重振込防止（作成済みは選べない）、同時操作の排他、記録の2回目は409 |
| 自己承認 | 自分の口座を自分では確認できない（他に確認できる人がいる限り） |

## ファイル形式

120バイト固定長のレコードを CRLF でつないだテキスト（半角カナは1バイト文字）。

```
1 ヘッダ   区分1 / 種別2(21・11・12) / コード区分0 / 委託者コード10 / 委託者名40 / 振込指定日MMDD / 仕向銀行4+15 / 仕向支店3+15 / 預金種目 / 口座番号7
2 データ   銀行4+15 / 支店3+15 / 手形交換所4(空白) / 預金種目 / 口座番号7 / 受取人名30 / 振込金額10 / 新規コード0 / 顧客コード / 識別 / …
8 トレーラ 合計件数6 / 合計金額12
9 エンド
```

預金種目は 普通=1・当座=2・貯蓄=4（委託者側の貯蓄は9）。実装は `src/lib/zengin.ts`（副作用なしの純粋関数。テスト `tests/unit/zengin.test.ts`）。

## 注意（導入時に確認してほしいこと）

- 銀行ごとに細部（コード区分、振込指定日の扱い、取り込める文字）が少し異なります。**初回は銀行のネットバンキングの取り込み検証（または少額）で受け付けられることを確認**してください。
- 取引先口座の「確認済」にできるのは管理者のみです（経理担当は閲覧のみ）。
