# freee連携（お金の動きを取引として送る）

支払い済みになったお金を、freee会計に「銀行口座から支払った支出の取引」として登録します。**実際に払った金額と日付**で、1件ずつ**1回だけ**送ります。

> この連携は freee の公開API（OAuth2 と `POST /api/1/deals` など）の仕様に沿って作り、疑似サービス（`e2e/helpers/mattermost-mock.ts`）で確かめています。本物のfreeeでの動作確認（アプリの登録、勘定科目・税区分の選び方）は、導入時にお願いします。

## 何が送られるか

| 元になるもの | 送る金額 | 日付 | 科目の種類 |
| --- | --- | --- | --- |
| 給与明細（支払済） | 差引支給額（手取り） | 支払日 | 区分で決まる: 役員→役員報酬、業務委託・準業務委託→業務委託費、それ以外→給与 |
| 振込申請（振込済） | 振り込んだ額（申請額 − 控除 − 先方負担の手数料） | 振込日 | 振込申請 |
| 経費の立替金（返金済） | 申請の金額 | 返金日 | 経費（科目ごとの指定、なければ「経費の立替金」） |

- 給与明細に合算された立替金は、**その明細の取引の中で**経費の科目に分けて送ります（別の取引にはしません）。
- 「連携の開始日」より前に支払ったものは送りません（すでにfreeeに入っている想定）。
- 支払前（支払予定・承認済み・却下）のものは送りません。
- 税区分は freee の税区分コードを割り当てで指定します（初期値 0 = 対象外）。給与・報酬は対象外、経費は課税仕入などになるため、税理士さんに確認してください。

## 証憑（領収書・請求書）も一緒に送る

取引といっしょに、**証憑**（領収書・請求書の画像やPDF）を freee の「ファイルボックス」に入れて、その取引に紐づけます（`POST /api/1/receipts`、取引の `receipt_ids`）。

| 取引 | 送る証憑 |
| --- | --- |
| 経費の立替金 | その経費に添付した領収書（最大5枚） |
| 給与明細 | 明細に合算した経費の領収書 |
| 振込申請 | 申請に添付した請求書など |

- 証憑は**取引より先に**アップロードします（freee の取引から指すため）。アップロードした証憑の freee 側の ID は `freee_exports.receipt_map` に記録し、**再送のときに同じファイルを二重にアップロードしません**。
- 証憑を1つでも送れなかったときは、**取引は作らず**、失敗として一覧に残します（「証憑「○○.pdf」を送れませんでした: …」）。直ったら「再送する」で、送れていなかった分から続きを送ります。証憑のない取引は、これまでどおり取引だけです。
- ディスクから消えていた証憑のファイルは飛ばして、取引は送ります。
- 一覧には「証憑 2件を紐づけ」と出ます。
- **管理 › システム設定 › freee連携**の「証憑（領収書・請求書）も一緒に送る」で切り替えられます（初めはオン。オフなら取引だけ送ります）。
- freee 側の決まり（ファイルの種類・大きさの上限など）は、freee の仕様に従います。アプリが受け付ける領収書は、画像かPDFで1枚10MBまでです。

## 設定（システム管理者）: 管理 › システム設定 › freee連携

1. **freeeアプリの情報**: freeeの開発者向けサイトでアプリを作り、「コールバックURL」に画面に出るURL（`{アプリのURL}/api/freee/callback`）を登録。Client ID と Client Secret を保存（Secret は暗号化して保存し、画面には返しません）。
2. **接続**: 「freeeに接続」→ freeeの画面で許可すると戻ってきます。会社が1つならその会社が自動で選ばれ、複数なら選びます。
3. **口座**: お金が出ていく銀行口座（freeeの口座）を選びます。
4. **勘定科目**: 給与・役員報酬・業務委託費・振込申請・経費（科目ごと）に、freeeの勘定科目と税区分コードを割り当てます。
5. **送る範囲と自動送信**: 「この日以降に支払ったものを送る」を決め、自動送信をオンにできます（会社・口座・開始日が決まってから）。

トークン（アクセス・リフレッシュ）は `ENCRYPTION_KEY_HEX` で暗号化して `app_settings` に保存します。アクセストークンが切れると、リフレッシュトークンで自動的に取り直します（リフレッシュトークンは1回しか使えないため、取り直しは1回に1つだけ）。

## 送信（経理担当・管理者）: 振込データ › freee連携

- 「送信待ち」（支払い済みで未送信）・「失敗」・「送信済み」の件数と、一覧が出ます。**今すぐ送る**で送ります。
- 自動送信がオンなら、振込済・支払済にした直後と、定期処理（同期の間隔ごと）で送られます。freeeが落ちていても、振込済にする操作は止まりません。
- 失敗した理由（勘定科目の未設定、freeeの応答など）が一覧に出ます。**再送する**か**送らない**（freeeに手で入れた場合など）を選べます。送信済みのものは再送できません。
- 送信の途中でサーバーが止まったものは、freeeに入ったか分からないので、自動では再送しません。freeeを確認してから「再送する」か「送らない」にします。
- 2人が同時に押しても、同じ取引が2つできないようにしています（1件ずつ「送信中」と記録してから送る）。

## 仕組み（開発者向け）

- `src/lib/freee.ts`: 接続・トークン・API呼び出し（会社・口座・勘定科目・取引）。`FREEE_AUTH_URL` / `FREEE_API_URL` でアドレスを差し替えられます（テスト用）。
- `src/lib/freee-sync.ts`: 支払い済みの集め方（`collectMovements`）、取引の組み立て（`dealDetails`）、送信（`syncToFreee`）、自動送信の合図（`triggerFreeeSync`）。
- `freee_exports` テーブル: 元（`source_type` + `source_id` は一意）ごとに、状態（`pending` / `sending` / `sent` / `failed` / `skipped`）、freeeの取引ID、エラー、試行回数。
- API: `GET/PUT/DELETE /api/admin/freee`、`GET /api/admin/freee/options`、`GET /api/freee/auth`・`callback`、`GET /api/freee/exports`、`POST /api/freee/sync`、`POST /api/freee/exports/:id`（`retry` / `skip`）。
- 設定のキー（`app_settings`）: `FREEE_CLIENT_ID` `FREEE_CLIENT_SECRET` `FREEE_ACCESS_TOKEN` `FREEE_REFRESH_TOKEN` `FREEE_TOKEN_EXPIRES_AT` `FREEE_COMPANY_ID` `FREEE_COMPANY_NAME` `FREEE_WALLETABLE` `FREEE_ACCOUNT_MAP` `FREEE_AUTO_SYNC` `FREEE_SYNC_FROM`。

## まだやっていないこと

- 発生主義の仕訳（給与の総支給・源泉・社会保険の内訳、請求書の計上と支払の分離）。送るのは「お金が出ていった事実」だけで、内訳は税理士さんがfreeeで調整する想定です。
- 取引先（freeeの取引先マスタ）との紐付け。摘要に相手の名前を入れています。
- freeeから銀行口座の入出金を取り込んでの突合。
